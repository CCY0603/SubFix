## 用户需求

在「生成选区字幕」的"文稿匹配"功能中，加入语义/标点优先的断句算法，替换当前仅按换行切分的简单逻辑，使字幕行在语义边界与标点处断开并遵循中英文标点规范。

## 产品概述

文稿匹配允许用户粘贴/导入文稿，用本地 Qwen3 强制对齐器把文稿对到选区音频时间轴，字幕文字严格等于文稿。当前实现把每一行（换行）当作一条字幕，断句粗糙。新增断句规则后，字幕行在语义边界与标点处断开，更自然且符合影视字幕习惯，同时保留"文字=文稿"的一致性。

## 核心功能

- 通用：断句发生在语义边界（从句/短语结束），绝不在单词或词组中间断开（如不能把 "the / contract" 分两行）；保持语法结构完整（名词与冠词/形容词、介词与宾语、动词与主语代词不拆散）。
- 中文：以内容为依据断句（不简单按字数）；顿号转空格，保留书名号《》、间隔号·；逗号分行；句号、感叹号、问号在一段末尾直接删除，在一段中间视为分行。
- 英文：在标点符号之后或在连词、介词之前断行；用省略号（…）表示话语停顿或未完，用两个连字符（--）表示话语被突然打断。
- 复用对话框"每行最大字数"作为软约束：仅当某段过长时在最近语义边界进一步断开，绝不词中/词组中断。
- 断句与标点变换后的文本即对齐文本与字幕文本，仍满足"字幕文字严格等于（变换后）文稿"。

## 技术栈

- 宿主：DaVinci Resolve Fusion Lua 脚本（UIManager）。目标文件 `.subfix_support/subfix_generate_selection_core.lua`。
- 下游 Python：`subfix_asr_transcribe.py` 的 `script_match_align` 模式（transformers 版 Qwen3ForcedAligner 强制对齐）无需改动。
- 纯 Lua 文本处理，无新增第三方依赖；复用既有 `trim_text`。

## 实现方案

### 高层策略

在 Lua 侧、构造 `script_rows` 之前，新增断句流水线：先按用户粘贴的**显式换行硬断**（尊重手动分段），再对每个非空块做**标点/语义软断**；最后用"每行最大字数"做**软长度约束**（仅在超长时于最近语义边界再断）。断句与标点变换在同一步完成，产出的最终文本即对齐与字幕文本。

### 关键设计

1. **语言判定**（块级）：`detect_segment_language(block)` 统计 `[A-Za-z]` 与 CJK 占比；英文占比高→英文规范，否则中文规范（块内混排默认中文处理，仍按标点断）。
2. **标点归一** `normalize_script_segment(text, lang)`：

- 通用：ASCII 省略号 `...`→`…`；连续的 `-`/`—`→`--`（表示打断）。
- 中文：顿号 `、`→空格；保留《》·；`，；：` 作为断点标记；`。！？` 段末删除、段中视为断点。
- 英文：`, ; : ! ? .` 作为断点；段末 `.!?` 删除、段中视为断点。

3. **断点识别** `segment_block_by_punctuation_and_structure(block, lang)`：

- 中文：在 `，；：` 之后、`。！？` 处切分；因中文无词间空格，仅在标点处切即可满足"不在词组中间断"。
- 英文：在 `, ; : ! ? .` 之后切分；并在连词/介词（`and/or/but/because/if/when/in/on/at/for/with/to/of/as` 等）**之前**切分；用 `%s(词)%s` 严格空白边界，避免把 "into" 中的 "to"、"only" 中的 "on" 误判。

4. **软长度约束** `find_best_break_point(seg, lang, max_chars)`：当某段 `> max_chars` 时，从 `max_chars` 向前回溯到最近断点（标点后 / 连词介词前 / 英文词边界）；英文绝不让字母跨边界；中文回退到标点或最近字边界（宁可略超也不拆词）。
5. **主入口** `split_script_into_subtitle_rows(script_text, max_chars)`：换行硬断→逐块软断→逐段软长度再断→去空→返回 `{text=...}` 列表，直接替代原 4408-4414 行的换行切分。

### 性能与可靠性

- 文本量级小（通常数百字），O(n) 线性处理，无性能风险；断点用预编译 `string` 模式，不重复遍历。
- 空文稿：返回 0 行，命中既有"文稿内容为空"分支报错，不会崩溃。
- 与既有单源/多源对齐、解析、合并、写回完全解耦——只改变 `script_rows` 的内容与条数，下游 `parse_generated_json_subtitle_rows` 与合并逻辑按 `text/start_frame/end_frame` 消费，无需改动。
- 日志：断句为纯本地文本变换，不引入外部调用，无需新增日志；若需调试可复用现有 `print("[SubFix Generate] ...")` 风格输出断句条数。

### 关键结构（示意）

```
-- 块级语言判定：英文占比高视为英文，否则中文
local function detect_segment_language(block)
  local letters, total = 0, #block
  for _ in block:gmatch("[A-Za-z]") do letters = letters + 1 end
  return total > 0 and (letters / total) > 0.4 and "en" or "zh"
end

-- 主入口：显式换行硬断 -> 逐块标点/语义软断 -> 软长度再断 -> 去空
local function split_script_into_subtitle_rows(script_text, max_chars)
  max_chars = tonumber(max_chars) or 25
  local rows = {}
  for raw in (script_text .. "\n"):gmatch("(.-)\n") do
    local block = trim_text(raw)
    if block == "" then goto continue end
    local lang = detect_segment_language(block)
    for _, seg in ipairs(segment_block_by_punctuation_and_structure(block, lang)) do
      for _, piece in ipairs(soft_break_by_length(seg, lang, max_chars)) do
        local t = trim_text(piece)
        if t ~= "" then rows[#rows + 1] = {text = t} end
      end
    end
    ::continue::
  end
  return rows
end
```
