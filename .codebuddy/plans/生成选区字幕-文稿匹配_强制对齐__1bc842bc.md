## 用户需求

在「生成选区字幕」对话框中新增「文稿匹配」功能：用户可粘贴文稿或从 `.txt` / `.srt` 文件导入文稿；启用后改用本地 Qwen3 强制对齐器，把文稿文本强制对齐到 In/Out 选区的音频时间轴，使生成的字幕文字严格等于文稿内容。文稿仅在本次生成会话的内存中使用，不落盘保存。

## 产品概述

面向 DaVinci Resolve 的字幕生成增强：在现有「生成选区字幕」对话框增加文稿来源，让"持有完整文稿"的用户直接得到文字精确、且时间轴对齐音频的字幕，而不依赖识别引擎的听写准确度。

## 核心功能

- 主对话框新增「文稿匹配」勾选开关与「文稿…」入口按钮（沿用现有 ☑/☐ 风格）。
- 文稿子窗口：多行文本框粘贴文稿 + 「导入…」按钮（`.txt` 纯文本 / `.srt` 抽取文本行）+ 清空 + 确定/取消。
- 启用文稿匹配后，生成流程切到本地 Qwen3 强制对齐：文稿按行（或按字幕长度自动断句）作为对齐输入，选区音频按时间线顺序拼接为单条，对齐后输出带时间轴的字幕行。
- 字幕文字严格等于文稿；时间轴由对齐器给出；下游解析/合并/写回时间线逻辑与现有生成流程完全一致。
- 文稿不写入磁盘，关闭对话框即失效。

## 技术栈

- 宿主：DaVinci Resolve Fusion Lua 脚本（UIManager，Qt 控件）；复用现有 `.subfix_support/subfix_generate_selection_core.lua` 与 `subfix_asr_transcribe.py`。
- UI：Fusion UIManager 声明式控件（Button / TextEdit / Label），沿用 ☑/☐ Button 勾选视觉风格。
- 文件选择：`fusion:RequestFile`（宿主注入全局），不可用时回退为手动路径输入框。

## 实现方案

高层策略：在 `generate_selection_subtitles` 的"获取原始字幕行"环节做条件分支——启用文稿匹配时跳过 ASR 识别，改为构造文稿对齐批量计划并调用 Python 强制对齐，得到与现有 `subtitle_rows` 同构的行数据，下游解析/合并/写回全部复用，保证最小改动面。

关键决策：

1. 复用并扩展 Python 强制对齐能力：在 `subfix_asr_transcribe.py` 新增文本对齐模式（如 `script_match_align`），直接接收"音频源列表 + 文稿行 + fps + timeline_start_frame"，内部用 ffmpeg 按时间线顺序拼接音频、调用 Qwen3 强制对齐器，并输出顶层 `subtitle_rows`（与 `generate_subtitles_batch` 同 schema），使 Lua 侧零改动复用 `parse_generated_json_subtitle_rows` 与写回链。
2. 对齐器就绪性：优先复用 `qwen_forced_align_text_batches` 的 cpp(GGUF) 路径（`qwen3_cpp_forced_align_text_rows`）；若其未就绪而 installer 已下载的 HF `Qwen3-ForcedAligner-0.6B` 可用，则改用 transformers 版对齐入口。实现前须用 [subagent:code-explorer] 核查 `resolve_qwen3_cpp_paths` 与 `ensure_forced_aligner` 的实际产物。
3. 文稿→rows 切分：默认按换行每条=一行字幕；可选按「字幕长度」max_chars 预切分长行，由对齐器按行给时间轴。
4. 多源音频：单源直接用其路径；多源在 Python 内按 `start_frame` 排序后用 ffmpeg concat 合并为单条再对齐，`timeline_start_frame` 偏移保证绝对时间轴正确。
5. 启用文稿匹配时忽略「识别模型」（Doubao/Qwen）选择，强制本地 Qwen 对齐；UI 置灰引擎按钮并提示。
6. 不落盘：文稿仅存对话框闭包变量。

## 实现要点

- 复用 `write_generate_batch_plan` 的音频源字段结构（`audio/source_start/source_end/start_frame/fps`），新增文稿对齐专用 batch plan 写入（单行 `audio_sources` + `rows`）。
- 复用 `run_asr_helper_batch_with_progress` 的进度窗口机制（避免命令框闪烁）；ffmpeg/对齐器执行走已有隐藏窗口（`ShellExecuteW` SW_HIDE）路径。
- 错误与回退：对齐失败给出明确错误并保留原对话框；对齐器缺失时复用 4116-4122 的安装/提示流程。
- 性能：拼接/对齐仅一次；长音频受对齐器长度限制，超长时按源分段对齐并在 Lua 侧合并（实现时按实测决定）。

## 架构设计

```mermaid
flowchart LR
  A[主对话框: 勾选文稿匹配 + 子窗口粘贴/导入] --> B[generate_selection_subtitles 分支]
  B --> C[确认 Qwen 对齐器就绪]
  C --> D[写文稿对齐 batch plan: audio_sources + rows + fps + timeline_start_frame]
  D --> E[subfix_asr_transcribe.py 文本对齐模式: ffmpeg 拼接 + Qwen3 强制对齐]
  E --> F[输出 subtitle_rows JSON]
  F --> G[parse_generated_json_subtitle_rows 复用]
  G --> H[合并 + 写回时间线 复用]
```

现有 ASR 分支保持不变；仅「获取原始字幕行」一步被条件替换。

## 关键结构

文稿对齐 batch plan（JSON）片段示例：

```
{
  "audio_sources": [
    {"audio": "<path>", "source_start": 0.0, "source_end": 12.3, "start_frame": 0, "fps": 30}
  ],
  "rows": [{"text": "文稿第一行"}, {"text": "文稿第二行"}],
  "fps": 30,
  "timeline_start_frame": 1000
}
```

Python 输出 `subtitle_rows` 沿用现有 row 结构：`{index, start_frame, end_frame, text, ...}`（对齐器 `aligned_rows` 已含这些字段，直接透传即可被 `parse_generated_json_subtitle_rows` 消费）。

## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 实现前核查 Qwen3 强制对齐器就绪情况（cpp GGUF 路径 `resolve_qwen3_cpp_paths` 与 installer `ensure_forced_aligner` 实际产物），以及音频批量计划字段结构与多源拼接可行方式，避免盲目选定对齐路径。
- Expected outcome: 明确文稿匹配应走 cpp(GGUF) 还是 HF `Qwen3-ForcedAligner` 路径，并给出 batch plan 字段与 ffmpeg 拼接的可靠实现依据。
